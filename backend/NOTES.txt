MINCO BACKEND — NOTES
======================
Written: Sep 2026. Live at: https://aaize09.pythonanywhere.com

WHAT IT IS
---------
A small Python web server (Flask + SQLite) that powers the Minco site:
real user accounts, a shared feed, and the helper-chat endpoint. It also
serves the frontend pages themselves, so site + API live on one URL.

STACK
-----
- Flask (web framework) + Flask-Cors
- SQLite via Python's built-in sqlite3 module (no ORM)
- gunicorn (production server; used by Render-style hosts, not PA)
- Passwords hashed with Werkzeug scrypt — never stored in plain text
- Login sessions = random tokens stored in the `sessions` table,
  sent as `Authorization: Bearer <token>` headers

FILES (in backend/)
-------------------
- app.py ........................ the whole backend (routes + database + chat rules)
- requirements.txt .............. Flask, Flask-Cors, gunicorn

- README.md ..................... setup + deploy instructions

DATABASE TABLES (inside minco.db)
---------------------------------
- users(id, name, email UNIQUE, password_hash, created_at, bio, avatar)
  (bio/avatar added later via ALTER TABLE migration in init_db — old DBs upgrade
  automatically on boot)
- sessions(token, user_id, created_at)
- posts(id, user_id, name, community, tag, text, image, ups, downs, loves, created_at)
- votes(post_id, user_id, value) .... one row per user per post
- loves(post_id, user_id) ........... one row per support given
- replies(id, post_id, user_id, name, text, created_at)
- meetings(id, user_id, name, title, description, link, topic, starts_at,
  duration_min, rsvps, created_at) + meeting_rsvps(meeting_id, user_id)
  (awareness meetings board: post sessions, RSVP toggle, owner delete)
- resources(id, user_id NULL for seeds, name, kind, title, description, url,
  topic, created_at) — article/video/podcast library, 18 link-verified seeds
  (7 articles: NHS x2, WHO x3, HelpGuide, Sleep Foundation; 7 videos incl.
  Indiana Univ. + Epworth + AskDoctorJo; 4 podcasts incl. Happiness Lab).
  Seeds insert-if-missing BY URL so old DBs gain new seeds on boot.
  Seeds are NULL-owner so the owner-only DELETE can never remove them.
- moods(id, user_id, date YYYY-MM-DD, mood, score 1-5, note, created_at),
  UNIQUE(user_id, date) — one check-in per day, re-saving overwrites.
  Moods: awful=1, low=2, okay=3, good=4, great=5.

Seeded automatically on first start: demo user demo@minco.app / minco123
plus 4 starter posts and 1 reply. Delete minco.db anytime to reset all data.

API ENDPOINTS
-------------
- GET  /api/health .............. health check (frontend uses this to detect backend)
- POST /api/register ............ {name, email, password} -> {user, token}
- POST /api/login ............... {email, password} -> {user, token}
- GET  /api/me .................. current user (needs token)
- PUT  /api/me .................. update name/bio/avatar; renames past posts+replies
- POST /api/logout .............. invalidate token (needs token)
- GET  /api/posts ............... feed (?sort &community &q, plus &mine=1 for own posts)
- GET/POST /api/meetings ........ awareness board (post future-dated sessions with
  video link; RSVP toggle at POST /api/meetings/<id>/rsvp; owner DELETE)
- GET/POST /api/resources ........ library (kind/topic/search filters; sharer DELETE).
  Frontend embeds YouTube + Spotify inline, rest opens externally.
- POST /api/posts ............... new post {text, community, image?} (needs token)
- POST /api/posts/<id>/vote .... {value: 1, 0 or -1} (needs token)
- POST /api/posts/<id>/love .... toggle support (needs token)
- POST /api/posts/<id>/replies . {text} (needs token)
- POST /api/moods ................ {mood, date?, note?} upsert one check-in
  per day (validates mood/date, rejects future dates; needs token) -> {mood, weekly}
- GET  /api/moods ................ own check-ins (?days=31) + weekly summary
  {avg, count, low, days} — low = avg < 2.5 with 2+ check-ins (needs token)
- POST /api/chat ................ {message} -> {reply, crisis} (offline rules for now)

HOW THE FRONTEND CONNECTS
-------------------------
- assets/js/api.js talks to the same server that served the page by default,
  checks /api/health, and remembers a working server. Backend up -> real API.
  Backend down -> pages silently fall back to localStorage demo mode.
- auth.js tries /api/register and /api/login first, falls back offline.
- mood.js (home page): daily check-in popup + calendar + weekly score,
  backend-first with localStorage fallback (minco_moods_v1), prompts once/day.
- home.js pulls the feed from /api/posts and syncs votes/loves/replies/posts.
- chat.js tries /api/chat first, falls back to its built-in offline answers.
- Override the server manually: localStorage.setItem("minco_api_base", "http://...")

LESSONS FROM DEPLOYING (things that bit us)
-------------------------------------------
1. Virtualenv path must be the VENV (/home/aaize09/.virtualenvs/minco),
   not the repo folder. The dot in .virtualenvs matters.
2. "Something went wrong" = generic page; the real error is in the Error log
   on the Web tab — always check there first.
3. WARNING: Package(s) not found: flask -> pip install -r requirements.txt
   had never run inside the venv. Fix: workon minco, then pip install.
4. Linux paths are case-sensitive: minco-web != Minco-Web. The WSGI sys.path
   and Source code dir must match the real folder name exactly.
5. Never run `python app.py` on PythonAnywhere — just press Reload.
6. render.yaml exists for Render hosting, but Render signup asks for a card,
   so PythonAnywhere is the current home.
